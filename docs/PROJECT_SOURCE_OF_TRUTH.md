# Accounting Workshop — Project Source of Truth

این مخزن از این مرحله به بعد مخزن اجرای پروژه حسابداری کارگاه تدوین‌شده در سابقه پروژه است؛ محتوای prototype قبلی مرجع نیازمندی نیست.

## ده بخش عملیاتی نهایی
1. تنظیمات
2. کالاها
3. تاریخچه_قیمت
4. مشتریان
5. فروش
6. چک_ها
7. موتور_حساب
8. حساب_جاری
9. بستن_ماه
10. داشبورد

Operation، Effect، AuditLog، Schema Registry و ReceiptAllocation مفاهیم زیرساختی/دامنه هستند و نباید به‌عنوان شیت عملیاتی اضافی به فایل نهایی تحمیل شوند.

## قراردادهای مالی تثبیت‌شده
- تسویه FIFO از قدیمی‌ترین فروش واجد شرایط.
- چک/دریافت برگشتی یا باطل اثر اقتصادی جاری ندارد.
- چک آینده تا تاریخ مؤثر در مانده وصول‌شده وارد نمی‌شود و برای پیش‌بینی نگهداری می‌شود.
- tier بر اساس اولین سقف روز فعال که مدت واقعی را پوشش دهد انتخاب می‌شود و نرخ انتخاب‌شده برای کل مدت واقعی اعمال می‌شود.
- سود تأخیر اطلاعاتی است و اصل بدهی را افزایش نمی‌دهد.
- اعتبار مشتری از مازاد دریافت محاسبه می‌شود، نه دستی.
- ReceiptAllocation نسخه‌دار و غیرقابل تغییر است.
- قرارداد ۶ آرگومانی CREDIT_VALUE مرجع محاسبات Sheets باقی می‌ماند.

## قرارداد عملیات
عملیات حساس دارای OperationID، IdempotencyKey و CorrelationID هستند. رکورد POSTED حذف یا overwrite نمی‌شود. اصلاح با reversal و operation جدید انجام می‌شود. عملیات چنداثری پشتیبانی می‌شود. شکست پس از ثبت اثرها باید به NEEDS_REPAIR برسد و فقط از مسیر repair کنترل‌شده نهایی شود. Audit append-only است.

## مرز معماری
UI → Application Services → Operation Boundary → Domain/Financial Engine → Repository

این مرحله هنوز ادعای اجرای واقعی Google Apps Script Cloud Runtime یا Supabase/PostgreSQL را ندارد؛ این‌ها گیت‌های بعدی هستند.
